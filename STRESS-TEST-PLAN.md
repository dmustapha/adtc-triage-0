## Phase execution map

1. Frontend journey: use Playwright or a Chromium fallback against an owned ephemeral `127.0.0.1` listener exported from `src/server.ts`.
2. End-to-end flows: hold deterministic SSE through terminal state; probe but do not fake unavailable QVAC/model-backed flows.
3. Visual and accessibility: capture `/app` at all five viewports, inspect overflow, console, keyboard focus, semantic labels, and truthful online/runtime evidence.
4. Backend API: execute all implemented synchronous routes and methods, malformed/oversized bodies, concurrency, and state checks.
5. Contract: skip smart-contract probes because the architecture explicitly contains no smart contract.
6. State and data: corrupt browser storage and response shapes, refresh, and verify fail-closed behavior.
7. Network and timing: offline toggle, loopback-only trace, delay, rapid actions, cancellation, and retry behavior.
8. Recovery: owned listener restart, refresh/back navigation, failed-runtime state, and process cleanup.
9. Fix round: root-cause analysis, focused RED, minimal GREEN, regression tests, and narrow commit for any proven local defect.

## Success and stop rules

- Every planned case receives PASS, FAIL, or an exact prerequisite SKIP.
- A missing model, QVAC store, named clinical review, physical Ubuntu run, signed decision, or final media is not converted into a pass.
- Any fix requires a reproducible failure and a failing automated test first.
- Every listener or browser process started by Stress is owned and stopped before completion.
